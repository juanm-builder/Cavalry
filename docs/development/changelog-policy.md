# Changelog policy

Record user-visible behavior, workbook compatibility changes, security fixes, integration contract changes, and release limitations in release notes. Pure refactors, formatting, and test-only changes do not need user-facing entries unless they alter supported workflows.

Each release record should include the version, date, signing/notarization status, validation evidence, migration notes, and known limitations. The GitHub release record must identify the immutable source commit SHA; the committed changelog does not need to reference its own commit. Never include private vulnerability details before a fix is available.
