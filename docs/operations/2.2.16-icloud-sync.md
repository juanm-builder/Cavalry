# Cavalry 2.2.16 iCloud sync repair

## Failure and scope

This fix starts from published Mac 2.2.15 (`26a48e9`) and pairs with iOS 1.0.14,
which starts from iOS 1.0.13 (33). Unrelated work in the primary checkouts was
preserved. No workbook schema, Apple Account, or CloudKit container is changed.

A save collision produces `CKError.serverRecordChanged`. Both native clients
previously passed its `serverRecord` straight to the complete snapshot decoder.
Apple explicitly states that this record's asset URLs are nil because assets
have not been downloaded. Requiring `payloadAsset.fileURL` therefore incorrectly
classified this normal conflict response as `cloud_snapshot_invalid` and then
made retry decisions from stale cached revision/change-tag information.

Source: [Apple CKAsset.fileURL documentation](https://developer.apple.com/documentation/cloudkit/ckasset/fileurl).
This is a reproducible mechanism matching the reported iPhone error, not a claim
that an affected-account trace was captured. The available local Mac uses a
different account; no live CloudKit diagnostic was run against that account.

## Repair

- Fetch the complete server record before interpreting a save collision. Keep
  the pending local edit if that fetch fails, and ignore results from a previous
  account/engine generation.
- Preserve failed record identities for bounded retry independent of the
  incremental change cursor. Recover older persisted snapshot failures without
  deleting the local cache or queued work.
- Retain encrypted-field, workbook identity, payload-size, and SHA-256 checks.
  Diagnostics name failing fields/types without including financial values.
- Refresh promptly while the apps are active so delayed push notifications do
  not leave an open device stale. Concurrent refreshes share existing work.
- Canonicalize browser-written timestamps to UTC ISO 8601 and read explicitly
  supported legacy timestamp variants consistently on native clients.
- Update two compatible transitive development dependencies to remove newly
  reported advisories. The dependency audit exception policy is unchanged;
  its cycle test now uses explicit dates and also verifies expiry.

## Verification and limits

All three native suites passed on both source trees, including real CKRecord
assetless collision fixtures, same-revision retry exhaustion, advanced-revision
conflicts, offline edit retention, replay, deletion, and owner-switch isolation.
Independent source review approved native SHA-256
`db1d32c0d116faa0df52e676cb6e1d5be9aa803e423e0c58752dcdbda84c80cd`
(Mac) and `f5219a8e40aee4ca3fa143b294bc4f416fabbb073ef91c0f8308a373f0887907`
(iOS). Signed builds and exact asset certification remain separate gates.
The regression fixtures are synthetic and never access a real iCloud account.

The affected physical Mac/iPhone pair is unavailable in this session. Automated
checks cannot establish its network latency, Apple push delivery, or final
post-update reconciliation. Real conflicts still require review instead of
silently choosing one device's edits. Background scheduling remains controlled
by Apple; the foreground fallback is not a background-sync timing guarantee.

No cloud workbooks or local finance files are deleted, reset, or overwritten as
part of deployment. Install the paired updates and open both apps to let the
recovery run. If a workbook still reports a problem, its details identify the
specific rejected field without exposing workbook contents.
