# Cavalry 2.2.13 Notes release certification

This record accompanies the Notes release candidate. It is not a claim that an unbuilt or
uncertified artifact has passed. Publication requires the completed artifact evidence described
below and independent review against [native certification](native-certification.md).

## Source and scope

The release integration branch starts from `v2.2.12`
(`e61fdb52eb3a1ab7cec5d2dad7ba80e96f9f5b18`). It retains that release's workbook recovery,
CloudKit account isolation, dependency patches, amount privacy, and Assistant/budget improvements.
The earlier working checkout was preserved separately. Its active Notes work and remaining
appearance changes were reconciled into this branch; it was not used to replace newer released
recovery code.

The candidate adds a review step before Notes transactions are saved, local draft recovery,
editable parsed entries, bounded AI output grounded in the original note, and explicit review of
possible duplicates. See [Notes evaluation](../features/notes-evaluation-2026-09-10.md) for the
synthetic inputs and behavioral results. No workbook schema or CloudKit migration is introduced.

## Evidence to archive before publication

- Immutable tag and commit, dependency lockfiles, release gate logs, and native Notes evaluation.
- Both native release jobs' signed sidecar startup and forced-recovery smoke results.
- Exact seven uploaded asset names, IDs, sizes, and SHA-256 hashes; tag/commit and immutable updater
  URLs checked by the release inventory verifier.
- App and DMG signing identities, strict signature validation, notarization/stapling evidence,
  target architectures, and cryptographic updater signature verification.
- Apple Silicon GUI checks on the downloaded release artifact and independent artifact review.
- A final statement that no certified asset was replaced after review. Replacing an asset requires
  the affected checks and inventory review to run again.

The local Apple Development build is a GUI candidate only. It does not substitute for the
Developer ID signed and notarized release assets produced by the tag workflow.

## Local candidate verification

The isolated integration checkout passed `npm ci` and the complete `npm run check` with Node
22.23.2: 2,497 source/renderer tests, formatting, lint, type checking, production asset builds,
architecture boundaries, runtime license inventory, and OpenAPI/instruction checks. An existing
recurring composition test was made deterministic by waiting for the bill's actual saved workbook
instead of accepting an earlier category save. Its persistence assertions remain intact.

The additional integration run passed 447 tests. End-to-end renderer/host asset smoke, native
CloudKit durability and account-event checks, `cargo fmt --check`, strict all-target/all-feature
Clippy, and `cargo check` passed. Release security scanned 111 reachable commits, found no source
or workflow violations, and reported zero desktop dependency advisories.

The Apple M1 Pro candidate on macOS 26.6.2 (25G83), Xcode 26.6, Rust 1.97.1, and Tauri CLI
2.11.4 passed strict deep signature verification and executed its signed packaged host and forced
workbook recovery smokes. GUI Notes results are recorded in the linked evaluation document;
release artifact signing and notarization remain separate gates.

## Rollback

Keep the preceding application bundle and a workbook backup before installing the candidate.
Reinstall the preceding signed Tauri release if native acceptance fails; do not delete workbook,
backup, or application-data directories. Notes drafts are device-local, so retain the current
profile when returning to the previous app. Published version tags and assets are immutable: a
post-publication fix uses a higher version rather than replacing certified files.
