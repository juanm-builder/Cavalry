Scope
-----
This handoff keeps the trust-critical finance work from the first v1.0.26
package and adds the requested interface refinement without advancing the
version number.

Financial behavior:
- First-class merchant refunds that reduce the original expense category.
- A central transaction-contribution model and calculation receipts.
- Monthly Plan separation for spending limits, recurring commitments, savings,
  debt, and expected income.
- Explicit unresolved-FX handling instead of guessed totals.
- Visible repair states for missing or archived plan categories.
- Bills headline totals that do not change when the table is searched or
  filtered.
- Normalized monthly equivalents for weekly, biweekly, monthly, quarterly, and
  yearly recurrence.
- Occurrence-first bill details, inactive-item restore access, per-item currency
  preservation, and zero-remaining fixes.
- Durable YYYY-MM sheet identities and cross-year month creation.

Interface refinement:
- Four primary Monthly Plan overview cards: Income plan, Spending plan,
  Recurring, and Unallocated. Savings and debt appear only when targeted.
- One tabbed Your plan list instead of the previous Budget Usage wall and
  multiple simultaneous plan sections.
- A compact monthly status and shorter default explanations, with deeper
  definitions behind More details.
- Wide, centered Monthly Plan detail dialogs rendered at document level so route
  transforms cannot collapse them into a thin rail.
- A viewport-centered Add to Plan editor with internal scrolling and persistent
  actions, so it does not open below the current page position.
- A Find recurring charges action that surfaces review-first suggestions from
  existing transaction-pattern analysis and opens a prefilled editor only after
  the user chooses Review. Nothing is created without an explicit Save.

AI boundary
-----------
No source files were changed under the Assistant, advisor runtime, Action Review,
Companion API, or local-model tooling directories. The v1.0.25 AI component is
intentionally preserved.

Because Action Review was left untouched, refunds created through the Assistant
or AI review path still use its legacy transaction assembly. Enter merchant
refunds through the standard transaction editor in this release.

The recurring-charge finder uses Cavalry's existing deterministic recurring
analysis. It does not change Assistant prompts, model calls, conversational
behavior, confirmation gates, or AI transaction assembly.

Compatibility and migration
---------------------------
- No workbook schema-version bump.
- Legacy month-index sheets receive a durable YYYY-MM monthKey during
  normalization and persist it on a later save.
- Historical refunds already stored as ordinary income cannot be inferred safely
  and require manual review.
- Recurring-charge detection is pattern-based and may need correction or miss
  irregular bills.
- Test first with a duplicate of the real workbook.

Environment-limited gates
-------------------------
The complete Vitest suite and Vite production build could not start in the Linux
packaging environment because the dependency tree supplied with the original Mac
archive contains the macOS Rollup binary and does not contain
@rollup/rollup-linux-x64-gnu.

The TypeScript gate could not start because the supplied dependency tree does not
contain @typescript/typescript-linux-x64.

The full Git-history security scan is unavailable from the source archive because
it intentionally contains no .git directory. The live npm dependency audit is
also unavailable because the packaging environment has no registry access. Run a
clean npm ci on macOS, then npm run check, npm run test:integration, and npm run
test:e2e before treating this source handoff as a release candidate.

This ZIP is source code, not a signed or notarized DMG.
